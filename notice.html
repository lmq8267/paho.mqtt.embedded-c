Eclipse 基金会软件用户协议

2011 年 2 月 1 日

内容的使用

Eclipse 基金会提供开源项目的软件、文档、信息和/或其他资料（统称“内容”）。使用本内容受本协议条款和/或以下指明或提及的许可协议条款约束。使用本内容即表示你同意，你对本内容的使用受本协议和/或任何适用许可协议的条款约束。如果你不同意本协议及任何适用许可协议的条款，则不得使用本内容。

适用许可

除非另有说明，Eclipse 基金会提供的所有内容均依据 Eclipse 公共许可证第 1.0 版（“EPL”）提供。EPL 副本随本内容一同提供，也可在 http://www.eclipse.org/legal/epl-v10.html 获取。就 EPL 而言，“程序”指本内容。

内容包括但不限于源代码、目标代码、文档以及在 Eclipse 基金会源代码库（“代码库”）中维护的其他文件，这些文件归类到软件模块（“模块”）并以可下载归档包（“下载包”）形式提供。

  • 为便于传递、扩展和升级内容，可将内容结构化并打包成模块。典型模块包括插件（“Plug-ins”）、插件片段（“Fragments”）和特性包（“Features”）。
  • 每个插件或片段可打包为目录或 JAR（Java™ Archive）文件，置于名为“plugins”的目录中。
  • 特性包（Feature）是由一个或多个插件和/或片段及相关资料组成的集合。每个特性包可打包为名为“features”的目录下的子目录。特性包内部名为“feature.xml”的文件可能列出与该特性包关联的插件和/或片段的名称及版本号。
  • 特性包还可能包含其他特性包（“Included Features”）。特性包内名为“feature.xml”的文件可能列出所包含特性包的名称及版本号。

插件和片段的许可条款应包含在名为“about.html”（“Abouts”）的文件中。特性包及其包含特性包的许可条款应包含在名为“license.html”（“Feature Licenses”）的文件中。Abouts 和 Feature Licenses 可位于下载包或模块中的任意目录，包括但不限于以下位置：

  • 顶层（根）目录
  • 插件和片段目录
  • 打包为 JAR 的插件和片段内部
  • 部分插件目录下“src”子目录中
  • 特性包目录

注意：如果 Eclipse 基金会提供的特性包是通过供应技术（Provisioning Technology）安装的，则在安装过程中你必须接受一份许可（“Feature Update License”）。如果该特性包包含其他特性包，则该 Feature Update License 应向你提供所包含特性包的许可条款，或告知你可在何处查找它们。Feature Update License 通常位于特性包内“feature.properties”文件的“license”属性中。这些 Abouts、Feature Licenses 和 Feature Update License 中可能引用 EPL 或其他许可协议、通知或条款与条件。

在使用本内容之前，你有义务阅读并接受上述全部条款与条件。如果未提供 About、Feature License 或 Feature Update License，请联系 Eclipse 基金会以确定适用于该内容的条款与条件。

供应技术的使用

Eclipse 基金会提供供应软件，例如 p2 和 Eclipse 更新管理器（“供应技术”），目的是允许用户安装软件、文档、信息和/或其他资料（统称“可安装软件”）。提供此功能旨在允许用户安装、扩展和更新基于 Eclipse 的产品。有关打包可安装软件的信息，请参阅 http://eclipse.org/equinox/p2/repository_packaging.html（“规范”）。

你可以使用供应技术允许他人安装可安装软件。你有责任确保向供应技术的用户展示并使其接受与可安装软件相关的适用许可协议，且展示和接受方式应符合该规范。通过按照规范使用供应技术并使其可用，即表示你进一步同意并获得必要权利，以允许以下行为：

  1. 用户可在某台机器（“目标机器”）上运行供应技术，以安装、扩展或更新基于 Eclipse 的产品，这一系列动作称为“供应流程”。
  2. 在供应流程中，供应技术可能访问并将第三方可安装软件或其部分复制到目标机器。
  3. 依据规范，你应向用户提供管理可安装软件使用的条款与条件（“可安装软件协议”），该协议须按规范要求在目标机器上可访问。可安装软件协议必须告知用户可安装软件的使用条款与条件，并按其要求征求最终用户的接受。在最终用户表示同意后，供应技术方可完成可安装软件的安装。
